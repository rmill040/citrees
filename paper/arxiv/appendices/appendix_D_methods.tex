\section{Algorithm and reproducibility notes}
\label{app:methods}

Algorithm settings, benchmark configuration, and coverage rules determine how
the main results should be read. Section~\ref{sec:method}
describes the tree-growing loop, the setup and proof appendices state the
fixed-node results, and Appendix~\ref{app:complexity-details} gives runtime and
memory details for the benchmarked tree-growing algorithm.

\subsection{Scope relative to the theory}

\Cref{app:theory-scope} states which fixed-node result covers which test and
under which conditions. The results cover the Stage~A feature test, the
per-threshold and max-type Stage~B threshold tests on any finite candidate set
fixed as a function of the node covariates (exact, random, percentile, or
histogram), threshold scanning, and adaptive stopping for Stage~A and
per-threshold Stage~B tests. The benchmarked tree-growing algorithm also uses
settings outside those results:
\begin{itemize}
  \item response-dependent feature muting,
  \item a Stage~B test of the feature that Stage~A chose from the same responses,
    and nodes reached through earlier response-dependent splits,
  \item bootstrap resampling and forest aggregation,
  \item optional honesty.
\end{itemize}
Stage~A and split scores from fitted trees are therefore tree-construction
scores.

\subsection{Node-level choices}

\paragraph{Stage~A.}
At each node, the tree-growing rule removes features that are constant on
the node before any feature subsampling. Stage~A computes $+1$ Monte
Carlo $p$-values. With feature scanning it tests features in order of their
observed statistic and stops at the first that meets the nodewise threshold,
independently of the stopping rule inside each permutation test. With
feature muting, features with non-rejecting Stage~A values can be removed from
descendant feature pools in the same subtree. These shortcuts reduce
computation. When they are active, the returned $q_t^{\mathrm{feat}}$ is the
feature-selection score used to grow the tree; the exhaustive fixed-$B$
reference value is defined over the full feature pool.

\paragraph{Stage~B.}
After Stage~A selects a feature, Stage~B builds thresholds from
midpoints between consecutive unique feature values. Exact search tests all
midpoints. Random sampling tests a bounded subset; percentile and histogram
rules test bounded representative thresholds from the midpoint distribution.
With sequential stopping, Stage~B may scan thresholds in a reordered sequence.
Because Stage~B tests thresholds only after a response-selected feature is
chosen, $q_t^{\mathrm{split}}$ is a split-selection score.

\paragraph{Split statistics.}
For permutation split testing, Stage~B uses weighted child impurity as the
tested statistic and a left tail convention. The final minimum
impurity-decrease filter uses the corresponding weighted impurity decrease.
These quantities support split construction.

\subsection{Permutation budgets and early stopping}

Both stages use Phipson and Smyth $+1$ Monte Carlo tail estimates
\citep{PhipsonSmyth2010PermutationPValues}: right-tailed in Stage~A and
left-tailed in Stage~B. For the benchmarked CIT and CIF configurations, the
resampling budget is set from the Bonferroni-adjusted nodewise threshold and is
large enough for rejection to be possible on the discrete $+1$ scale.

\paragraph{Sequential stopping.}
The benchmarked CIT and CIF configurations request adaptive sequential stopping,
whose rule monitors permutation exceedances and stops once a Beta posterior
places the configured confidence on one side of the nodewise threshold. Under
the \texttt{minimum} budget the first check coincides with exhaustion, so the
rule never acts and every benchmark $p$-value is a fixed-budget $+1$ permutation
$p$-value (\cref{prop:adaptive-size} and the remark following it); the rule acts
only at the larger budgets of the runtime ablations and at the \texttt{auto}
budget of the Stage~B construction study.

\subsection{Forests, resampling, and honesty}

CIF fits bootstrap trees and forms feature rankings by aggregating tree
split-importance vectors. The benchmark uses stratified bootstrap sampling for
classification and standard bootstrap sampling for regression. These forest-level
choices affect the fitted rankings, while the fixed-node results cover only the
nodewise reference tests.

\subsection{Benchmark coverage}

\Cref{sec:experiments-protocol,sec:experiments-repro} define the benchmark
protocol and configuration-selection rule. The benchmark compares 17
classification methods and 18 regression methods, including permutation-test
filters, embedded tree and ensemble methods, R ctree/cforest, and wrapper
methods. The rules below define which runs enter the appendix tables.

For per-method and direct pairwise summaries, each comparison uses the datasets,
downstream learners, and standard values of $k$ where the methods in that
comparison are present. Analyses that compare all methods restrict to datasets
with every method, downstream learner, and standard value of $k$ present. These
rules give 13 classification and 6 regression datasets for complete-case
analyses. On \nolinkurl{gisette}, \nolinkurl{isolet}, and
\nolinkurl{orlraws10P}, 34 classification runs were excluded from the benchmark
for operational reasons. Fifteen partykit ctree and cforest runs did not
complete on those datasets. Nineteen RDC-selector CIT and CIF runs were
excluded: 18 host-fault exclusions, in which the containers running the largest
RDC fits terminated without a Python exception because of a confirmed host
fault on the compute instances, while the other seeds of the same cells
completed; and one exclusion on \nolinkurl{orlraws10P} by author decision. The
locked cells are listed in \texttt{paper/benchmark/config/locked\_cells.csv},
which also lists the locked cells of the max-type extension; the file records
the cells locked at the time of writing, so its entries do not correspond one
to one with the seed runs of \cref{tab:coverage-skips}. Comparisons that involve
an affected method on an affected dataset use the remaining datasets.
\Cref{tab:coverage-skips} lists the excluded runs.

\subsection{Randomness and reproducibility}

The benchmark configuration fixes the seed schedule used for all reported
runs. Pure Python permutation routines use local \texttt{numpy} generators.
Numba parallel permutation paths assign one seed per resample, which avoids
sharing a mutable generator across parallel loop iterations.

\subsection{Mechanism-matched CIF check}
\label{app:cif-perm-check}

The benchmark ranks cforest by partykit's out-of-bag permutation importance and CIF by split importance, so the CIF-versus-cforest margin of \cref{tab:conditional-inference-comparisons} mixes the importance mechanism with the split procedure. To separate them, the selected CIF configuration of each task was refit on every Stage~1 fold of 20 classification and 8 regression real datasets, ranked by the mechanism cforest uses, one permutation of each feature on each tree's out-of-bag rows with the error increase averaged over the 100 trees, and scored with the Stage~2 protocol. The 20 classification datasets are the 22 on which CIF and cforest are paired in \cref{tab:conditional-inference-comparisons} less \nolinkurl{gisette} and \nolinkurl{letter}, which carry locked cells and were not refit; \nolinkurl{isolet} has no cforest run. \Cref{tab:cif-perm-check} reports the directed pairwise aggregate of \cref{sec:experiments-real}. Ranking CIF by out-of-bag permutation importance leaves the classification margin over cforest where it was: $+0.012$ mean and $+0.006$ median balanced accuracy with 15 wins of 20, against $+0.011$ and $+0.008$ for split-ranked CIF on the same datasets; the two CIF rankings differ by $+0.001$ on average and split wins 12 of 20. In regression the medians agree ($+0.006$ over cforest, $-0.002$ against split-ranked CIF) and the negative means come from one dataset, coepra2 ($n=76$, 5,144 predictors), on which every method has negative $R^2$ and the ridge and $k$-NN learners swing by whole units. In classification the margin is therefore not an importance-mechanism effect; in regression the medians agree and the mean is a single-dataset artifact, so the conclusion is stated for classification. Two notes on the check itself. Permutation importance computed on the training rows instead of out-of-bag (scikit-learn's default) is the wrong comparator: on the 16 datasets that completed it sits $0.10$ below cforest and $0.12$ below split-ranked CIF, the loss concentrated on the small-$n$, high-$p$ sets, while on spam it equals split-ranked CIF (0.900 against 0.901 at $k=10$). And the refit's split ranking overlaps the stored Stage~1 ranking poorly in the top ten on the high-$p$ sets (mean Jaccard 0.38 in classification), because most features never split there, their importances tie at zero, and the tie order is arbitrary; on the low-$p$ sets the overlap is complete.
