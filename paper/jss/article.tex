\Abstract{
  Conditional inference trees choose the split variable by a test of
  association and only then search for a cutpoint. This removes the advantage
  that variables with many possible cutpoints receive in greedy tree
  construction. \citrees is an open-source \proglang{Python} package that
  implements conditional inference trees and forests for classification and
  regression. Its four estimators follow the \sklearn estimator protocol, so
  they can be placed in pipelines and tuned by cross-validated search. Every
  node decision is a Monte Carlo permutation test, and its association
  statistic, level, multiplicity adjustment, permutation budget, and
  sequential stopping rule are constructor arguments. The fitted tree stores
  the $p$-values and sample sizes behind each split. The package also offers
  nonlinear association statistics, bounded threshold searches, a
  permutation test of the chosen threshold in a per-threshold Bonferroni form
  and a max-type form, feature muting, and separate samples for structure and
  leaf estimation. This article describes the procedure, the interface, and
  the implementation, and relates the package to \pkg{partykit} and \sklearn.
  A tutorial and a case study on the NHANES 2021 to 2023 diabetes cohort show
  the workflow. Validation studies measure the null calibration of the node
  tests, agreement with \pkg{partykit} under matched controls, and fitting
  time. The package, its documentation, and replication materials that
  regenerate every table are available under the MIT license.
}

\section{Introduction} \label{sec:introduction}

Classification and regression trees divide a predictor space into regions that
can be represented by a sequence of simple decisions. In the CART procedure,
the split variable and threshold are selected together by optimizing an
impurity criterion \citep{Breiman+Friedman+Olshen+Stone:1984}. Variables with
more admissible cutpoints therefore receive more opportunities to produce a
favorable split under noise. This mechanism is a documented source of
split-variable selection bias in trees and in forest importance measures
\citep{Strobl+Boulesteix+Zeileis+Hothorn:2007}.

Conditional inference trees separate the two decisions. A node first tests
predictor-response association and selects a variable, then searches for a
threshold only within that variable \citep{Hothorn+Hornik+Zeileis:2006}. The
framework is implemented in the \proglang{R} package \pkg{partykit}, which also
supplies infrastructure for recursive partitioning models
\citep{Hothorn+Zeileis:2015}. In \proglang{Python}, \sklearn provides mature
CART trees and forests and a common estimator interface for model selection
and pipelines \citep{Pedregosa+Varoquaux+Gramfort:2011}, but no conditional
inference estimator.

\citrees fills that gap, and its contributions are of two kinds. As software,
it provides conditional inference classifiers and regressors that follow the
\sklearn estimator protocol. They can be cloned, placed in pipelines, and
tuned by cross-validated search without a bridge to \proglang{R}. Every
statistical and computational choice is a constructor argument, and the
fitted tree stores the test results behind each split
(Section~\ref{sec:software}). As method, the package departs from
\pkg{partykit} in four places. Stage A uses Monte Carlo permutation $p$-values
of a user-chosen association statistic, including a variant of the randomized
dependence coefficient. An adaptive sequential stopping rule can end each
permutation test early. A second permutation test checks the chosen
threshold, in a per-threshold Bonferroni form and in a max-type form. Tree
structure and leaf values can be estimated on separate samples. The companion
article \citep{Milletich+Downes+Goley+Hirst:2026} gives the validity arguments
for these choices, the exact size of the stopping rule, and a
feature-selection benchmark. This article documents the interface and the
implementation, works through a case study, and reports the validation of the
software. Version 0.2.0 is installed from the repository with

\section[Conditional inference trees in citrees]{Conditional inference trees in \citrees} \label{sec:procedure}

At each internal node, a conditional inference tree makes two decisions. The
Stage A test checks each candidate predictor for association with the response
and selects one. The Stage B test then searches thresholds only for the
selected predictor. If either stage accepts nothing, the node becomes
terminal. Constructor arguments ending in \code{_selector} govern Stage A, and
those ending in \code{_splitter} govern Stage B.

\subsection{The Stage A test} \label{sec:screening}

Let $(X_t, y_t)$ denote the observations reaching node $t$, and let $F_t$ be
the nonconstant predictors considered at that node after any feature sampling
or muting. For predictor $j$, let $T_j$ be its association statistic and let
$T_{j,1},\ldots,T_{j,B}$ be the same statistic after $B$ random permutations
of the response. \citrees uses the Monte Carlo $p$-value
%
\begin{equation}
  p_j =
  \frac{1 + \sum_{b=1}^{B}
    \mathbb{1}\!\left\{T_{j,b} \geq T_j\right\}}
       {B + 1},
  \label{eq:permutation-p}
\end{equation}
%
whose smallest attainable value is $1/(B+1)$ \citep{Phipson+Smyth:2010}.
With multiplicity adjustment, predictor $j$ passes when $p_j < a$, where
$a = \alpha_{\mathrm{A}}/|F_t|$ is the adjusted level. Without adjustment,
$a = \alpha_{\mathrm{A}}$. The passing predictor with the smallest $p$-value
is selected, and exact ties are broken uniformly at random under
\code{random_state}.

The permutation budget is recomputed at each node from $a$. The
\code{"minimum"} setting uses $B = \lceil 1/a \rceil$, the first budget that
permits a $p$-value below $a$. The \code{"auto"} setting uses
$B = \max\{\lceil 1/a \rceil, \lceil z_a^2 (1-a)/a \rceil\}$ with
$z_a = \Phi^{-1}(1-a)$, and the \code{"maximum"} setting uses
$B = \lceil 1/(4a^2) \rceil$. An integer budget is multiplied by the number
of tests it must resolve, unless \code{scale_resamples_with_tests = False}
holds it fixed.

Classification selectors are multiple correlation, mutual information, and
the randomized dependence coefficient (RDC). Regression selectors are Pearson
correlation, distance correlation, and the RDC
\citep{Szekely+Rizzo+Bakirov:2007,Lopez-Paz+Hennig+Schoelkopf:2013}. The RDC
in \citrees differs from the original definition. After the copula transform
and random sine and cosine projections of both variables, it takes the largest
absolute Pearson correlation between a projected column of one variable and a
projected column of the other, rather than the first canonical correlation
\citep{Milletich+Downes+Goley+Hirst:2026}. The default of 10 projections is
examined in Section~S1 of the supplement. Bounded statistics can be combined
by passing a list, which gives a max-$T$ permutation test
\citep{Westfall+Young:1993}: each permutation records the largest configured
selector score.

Feature scanning tests candidates in order of the observed statistic and stops
at the first candidate that passes. Feature muting removes a predictor that
failed the Stage A test at a node from the candidate sets of that node's
descendants. Both are on by default.

Sequential stopping ends a permutation test before the full budget when the
decision is already clear. Let $k$ be the number of exceedances after $m$
permutations. Adaptive stopping, the default, is checked when $m$ is a
multiple of 32 or equals $B$, once $m \geq \lceil 1/a \rceil$. With
$\pi \sim \mathrm{Beta}(1+k, 1+m-k)$ the posterior of the exceedance
probability, it stops when
%
\begin{equation*}
  P(\pi < a) \geq c \quad \text{or} \quad P(\pi \geq a) \geq c ,
\end{equation*}
%
where $c$ is the confidence (default 0.95, also the smallest value allowed).
It reports $(1+k)/(1+m)$, which is compared with $a$. Simple stopping is
checked after every permutation beyond $\lceil 1/a \rceil$. It stops when
$(1+k)/(1+m) < a$, or when, after at least three exceedances,
$(1+k)/(1+B) \geq a$. Setting the argument to \code{None} runs the full
budget.

\subsection{The Stage B test} \label{sec:thresholds}

After Stage A selects predictor $j^\star$, Stage B constructs candidate
thresholds from the ordered unique values of $X_{t,j^\star}$. The
\code{"exact"} method uses every midpoint. The \code{"random"},
\code{"percentile"}, and \code{"histogram"} methods construct bounded subsets.
A histogram with $m$ bins yields up to $m+1$ candidates and never more than
the number of distinct values in the node, so 256 bins give 257 candidates on
a continuous predictor. Candidates that violate the minimum leaf size are
removed.

Each candidate is scored by the weighted impurity of its two children: Gini or
entropy for classification, squared or absolute error for regression. The
score is tested with response permutations at the Stage B level
$\alpha_{\mathrm{B}}$, and the node is terminal if no candidate passes. Two
tests control the error over the $K$ candidates. The per-threshold Bonferroni
test, the default, tests each candidate at level $\alpha_{\mathrm{B}}/K$ with
a budget computed at that level. Its cost is of order $K^2/\alpha_{\mathrm{B}}$
impurity evaluations per node. The max-type test standardizes each candidate's
impurity over the observed and permuted responses and compares the rank of the
observed minimum with $\alpha_{\mathrm{B}}$ directly
\citep{Westfall+Young:1993,Pollard+vanderLaan:2004}. It uses $B = 999$ and
costs of order $BK$. The companion article proves that both tests control the
probability of any split under the node's global null
\citep{Milletich+Downes+Goley+Hirst:2026}. The per-threshold test costs more
when $K^2/\alpha_{\mathrm{B}} > BK$, that is, when
$K > \alpha_{\mathrm{B}} B = 0.05 \times 999 \approx 50$. The max-type test is
selected with \code{threshold_test = "maxt"}. With threshold scanning,
candidates are tested in order of weighted impurity. Otherwise their order is
randomized under \code{random_state}.

\subsection{Forests, importances, and honesty} \label{sec:forests}

A conditional inference forest fits trees to bootstrap samples and can sample
a subset of predictors at each node. Classification forests can also use
stratified, under-, or oversampling. Predictions average class probabilities
or regression estimates across trees, and out-of-bag scores are available when
bootstrapping is on.

Tree feature importances sum the impurity decreases of the accepted splits on
each predictor and are normalized when their total is positive. Forest
importances average the normalized tree vectors. Stage A controls which
predictors may enter threshold search. The importance itself is impurity-based
and carries no $p$-value. With \code{honesty = True}, the training sample is
split, the structure is grown on one part, and the leaf values are estimated on
the other, which holds the fraction \code{honesty_fraction}
\citep{Wager+Athey:2018}.

\subsection{Scope of the guarantees} \label{sec:scope}

For a fixed node, a fixed predictor set, and a fixed budget,
Equation~\ref{eq:permutation-p} is an exact Monte Carlo permutation $p$-value.
At the default confidence and a 999-permutation budget, the adaptive stopping
rule has size 0.0488 for a fixed statistic; Proposition~1 of the companion
article derives this value exactly \citep{Milletich+Downes+Goley+Hirst:2026}.
Under the \code{"minimum"} budget with adjustment, the first check falls at the
full budget, so the rule never stops early. A fitted tree adds
response-dependent node creation, repeated tests, and threshold selection, so
the tree and forest analyses of this article target predictive behavior,
feature stability, and computation.

\section[Using citrees]{Using \citrees} \label{sec:software}

\citrees provides four estimators:
\begin{itemize}
\item \code{ConditionalInferenceTreeClassifier}, a classification tree;
\item \code{ConditionalInferenceTreeRegressor}, a regression tree;
\item \code{ConditionalInferenceForestClassifier}, a classification forest;
\item \code{ConditionalInferenceForestRegressor}, a regression forest.
\end{itemize}
They implement \code{fit()} and \code{predict()}, classifiers implement
\code{predict_proba()}, and fitted models expose \code{apply()},
\code{decision_path()}, and \code{feature_importances_}. Because they follow
the \sklearn conventions for constructor arguments and fitted attributes, they
work directly with \sklearn cross-validation, pipelines, and parameter search.

\subsection{A classification tree} \label{sec:tutorial}

The tutorial uses the Breast Cancer Wisconsin Diagnostic data
\citep{Wolberg+Mangasarian+Street+Street:1993}, with 569 observations and 30
continuous predictors. A stratified split assigns 426 observations to training
and 143 to evaluation. The following code fits a tree of depth at most 3. It
uses 32 histogram bins rather than the 256 of the benchmark configuration
(Section~\ref{sec:parameters}), which keeps the Stage B budget at each node to
660 permutations.
%
\begin{CodeChunk}
\begin{CodeInput}
>>> import json
>>> import numpy as np
>>> from citrees import (ConditionalInferenceForestClassifier,
...                      ConditionalInferenceTreeClassifier)
>>> from sklearn.datasets import load_breast_cancer
>>> from sklearn.metrics import balanced_accuracy_score, roc_auc_score
>>> from sklearn.model_selection import train_test_split
>>> data = load_breast_cancer(as_frame=True)
>>> X, y = data.data, data.target
>>> X_train, X_test, y_train, y_test = train_test_split(
...     X, y, test_size=0.25, stratify=y, random_state=1718
... )
>>> common = dict(
...     selector="mc",
...     n_resamples_selector="minimum",
...     n_resamples_splitter="minimum",
...     threshold_method="histogram",
...     max_thresholds=32,
...     random_state=1718,
...     verbose=0,
... )
>>> tree = ConditionalInferenceTreeClassifier(max_depth=3, **common)
>>> _ = tree.fit(X_train, y_train)
\end{CodeInput}
\end{CodeChunk}
%
The fitted tree is a nested mapping (Section~\ref{sec:inspection}), so a short
recursive function prints it. Each internal node shows its predictor, its
sample size, and its two $p$-values; each leaf shows its sample size and the
estimated probability of a benign tumor.
%
\begin{CodeChunk}
\begin{CodeInput}
>>> def show(node, names, indent=""):
...     if "value" in node:
...         print(f"{indent}leaf: n={node['n_samples']}, "
...               f"P(benign)={node['value'][1]:.3f}")
...         return
...     print(f"{indent}{names[node['feature']]}: n={node['n_samples']}, "
...           f"feature p={node['pval_feature']:.4f}, "
...           f"threshold p={node['pval_threshold']:.4f}")
...     show(node["left_child"], names, indent + "  ")
...     show(node["right_child"], names, indent + "  ")
>>> show(tree.tree_, tree.feature_names_in_)
\end{CodeInput}
\begin{CodeOutput}

  worst area: n=292, feature p=0.0017, threshold p=0.0015
    area error: n=273, feature p=0.0017, threshold p=0.0015
      leaf: n=255, P(benign)=0.965
      leaf: n=18, P(benign)=0.611
    leaf: n=19, P(benign)=0.158
  concavity error: n=134, feature p=0.0017, threshold p=0.0015
    leaf: n=130, P(benign)=0.023
    leaf: n=4, P(benign)=1.000
\end{CodeOutput}
\end{CodeChunk}
%
The tree has four internal nodes and five leaves. Every accepted split
attains the smallest $p$-values that its budgets allow: $1/601$ at Stage A,
from the \code{"minimum"} budget for 30 predictors, and $1/661$ at Stage B,
from the budget for 33 candidate thresholds. The root sends 134 training
observations with large worst concave points to the right, and all but four
of them fall in a leaf that is almost entirely malignant. The next code reads
the root split, the holdout metrics, the permutations the fit drew, and the
leading importances.
%
\begin{CodeChunk}
\begin{CodeInput}
>>> root = tree.tree_
>>> name = tree.feature_names_in_[int(root["feature"])]
>>> nodes = tree.decision_path(X_test).shape[1]
>>> print(f"tree: depth={tree.depth_}, nodes={nodes}, root={name}")
>>> print(f"root: threshold={root['threshold']:.4f}, "
...       f"feature p={root['pval_feature']:.4f}, "
...       f"threshold p={root['pval_threshold']:.4f}")
>>> bacc = balanced_accuracy_score(y_test, tree.predict(X_test))
>>> auc = roc_auc_score(y_test, tree.predict_proba(X_test)[:, 1])
>>> print(f"tree holdout: balanced accuracy={bacc:.4f}, ROC AUC={auc:.4f}")
>>> counts = tree.realized_permutation_counts_
>>> print(f"tree permutations: selector={counts['selector']}, "
...       f"splitter={counts['splitter']}")
>>> values = tree.feature_importances_
>>> order = np.argsort(-values, kind="stable")[:5]
>>> pairs = [f"{tree.feature_names_in_[i]}={values[i]:.4f}" for i in order]
>>> print("tree leading importances: " + ", ".join(pairs[:2]) + ",")
>>> print("  " + ", ".join(pairs[2:]))
\end{CodeInput}
\begin{CodeOutput}

\subsection{The fitted tree} \label{sec:inspection}

The attribute \code{tree_} holds the fitted tree as nested \proglang{Python}
dictionaries, one per node. A node is a leaf exactly when it has the key
\code{"value"}. Internal nodes carry \code{feature} (a column index),
\code{threshold}, \code{pval_feature} and \code{pval_threshold} (the Stage A
and Stage B $p$-values), \code{impurity} (the impurity of the node before the
split), \code{n_samples}, \code{node_id}, and the two children
\code{left_child} and \code{right_child}. Observations with
\code{x[feature] <= threshold} go left. Leaves carry \code{value}, which is
the vector of class probabilities for a classifier and the mean response for a
regressor, together with \code{n_samples} and \code{node_id}. Node identifiers
are assigned in preorder, the order in which \code{show()} above visits the
nodes. The estimator also exposes \code{feature_names_in_} (column names, or
\code{f1} to \code{fp} for arrays), \code{depth_}, and
\code{realized_permutation_counts_}, the number of permutations the fit drew in
each stage.

\subsection{Arguments and configurations} \label{sec:parameters}

Table~\ref{tab:parameters} lists the constructor arguments that control the
procedure and its cost. The four estimators share them. Forests add
\code{n_estimators}, \code{bootstrap}, \code{max_samples}, \code{oob_score},
\code{n_jobs}, and, for classification, \code{sampling_method}. They also
change the \code{max_features} default from \code{None} to \code{"sqrt"}.

The table defines three configurations. The default configuration is the
constructor defaults. It favors precise $p$-values over speed and is kept so
that results fit with earlier versions remain reproducible. The benchmark
configuration, used by the companion article and by the timing studies of
Section~\ref{sec:performance}, sets both budgets to \code{"minimum"} and uses
the histogram method with 256 bins. The recommended configuration, for feature
ranking on data of the size studied here, is the benchmark configuration with
the max-type test. It follows the crossover of Section~\ref{sec:thresholds}:
with more than about 50 candidate thresholds per node, the max-type test is
the cheaper valid test.

\section{Implementation} \label{sec:implementation}

This section describes how the package is organized, how the permutation
tests are computed, and which inputs \code{fit()} accepts.

\subsection{Architecture} \label{sec:components}

\citrees is written in \proglang{Python}, with its numerical kernels compiled
by \pkg{Numba} \citep{Lam+Pitrou+Seibert:2015}.
Table~\ref{tab:software-architecture} lists the modules. Association
statistics, permutation tests, split criteria, and threshold generators are
kept in internal registries, and the tree code resolves the requested
components by name during fitting. The registries are not part of the public
interface. A new statistic is added in the source, not by user registration.
Trees and forests share the same components, so classification and regression
behave in parallel.

Parameters are validated by \pkg{pydantic} models before fitting
\citep{Colvin:pydantic}. Validation enforces compatible selector
combinations, valid levels, feasible sample fractions, and forest settings with
defined outputs. Fitted estimators keep their constructor arguments unchanged,
as \sklearn cloning requires.

\subsection{Computation and parallelism} \label{sec:computation}

Permutation testing dominates the fitting time. The statistics and their
permutation loops are compiled kernels, and the permutations of one test run
in parallel threads. Each thread seeds \pkg{NumPy}'s generator with the
estimator seed plus the permutation index, so a fit is reproducible for a
given \code{random_state} and thread count. A forest derives one seed per tree
from its own seed.

Forests have two layers of parallelism. With the default \code{n_jobs = None},
trees are fit one at a time and each test uses the full thread pool. With
\code{n_jobs > 1} or \code{n_jobs = -1}, trees are fit in \pkg{joblib} worker
processes \citep{joblib} and the thread pool is divided among them, which
prevents oversubscription. When the Stage B test dominates the cost, as in the
benchmark configuration, the default layout is faster
(Table~\ref{tab:performance-reference}). Sequential stopping, threshold
bounds, and muting reduce the work further. Each of these controls changes the
computation and may change the fitted model, which is why each is an explicit
argument.

\subsection{Input handling} \label{sec:input}

\code{fit()} accepts \pkg{NumPy} arrays, nested lists, and \pkg{pandas} data
frames. Column names of a data frame become \code{feature_names_in_}. The
predictors are converted to floating point, so every column must be numeric,
and categorical predictors must be encoded numerically. Missing and infinite
values are rejected with an error, and sparse matrices are not supported. The
response must be one-dimensional. Classification labels may be strings, and
they are encoded internally.

\section{Relationship to existing software} \label{sec:comparison}

The \proglang{R} package \pkg{partykit} is the reference implementation of
conditional inference trees and forests
\citep{Hothorn+Hornik+Zeileis:2006,Hothorn+Zeileis:2015}. Its predecessor
\pkg{party} introduced the conditional inference forest and conditional
variable importance
\citep{Hothorn+Hornik+Strobl+Zeileis:party,Strobl+Boulesteix+Kneib+Augustin+Zeileis:2008}.
The two implementations differ at the node. \pkg{partykit} tests standardized
linear statistics, with asymptotic $p$-values by default and Monte Carlo
$p$-values on request. It adjusts them by Bonferroni over predictors, chooses
the split point by maximizing a standardized two-sample statistic, and stops
when the adjusted $p$-value is not below the level. Its forest defaults use
unadjusted $p$-values with no stopping level and subsampling without
replacement. \citrees tests a user-chosen association statistic with Monte
Carlo permutation $p$-values and sequential stopping, adjusts by Bonferroni
over predictors, chooses the split point by impurity, and can test the chosen
threshold with a second permutation test. \pkg{partykit} supports response
types, factor predictors, missing values, and display methods that \citrees
does not (Table~\ref{tab:software-comparison}). From \proglang{Python},
\pkg{partykit} can be called through \pkg{rpy2} \citep{Gautier:rpy2}, which
the replication suite uses.

\sklearn trees and forests jointly optimize a predictor and threshold by
impurity reduction. They fit more than 100 times faster than the benchmark
\citrees forest at the reference condition of
Table~\ref{tab:performance-reference}, and they remain the essential
baseline. \citrees pays for the nodewise association tests in exchange for
separating predictor screening from threshold search. Honest estimation, which
\citrees offers as an option, is central to the causal forests of \pkg{grf} in
\proglang{R} and \pkg{EconML} in \proglang{Python}
\citep{Wager+Athey:2018,Athey+Tibshirani+Wager:2019,Battocchi+Dillon+Hei:2019}.

\section{Case study: NHANES diabetes} \label{sec:nhanes}

The case study uses the public National Health and Nutrition Examination
Survey (NHANES) for August 2021 through August 2023 \citep{NCHS:2024}. It asks
whether the cardinality bias of impurity importance, which
Section~\ref{sec:cardinality} measures under the null, appears on real
clinical predictors. The cohort contains the 3,597 adults aged 20 or older
with a glycohemoglobin measurement and complete data on 27 predictors. The
outcome is diabetes, defined as glycohemoglobin of at least 6.5\% or a
reported physician diagnosis. The predictors are demographic items,
examination measurements, laboratory values, and questionnaire items. Their
numbers of distinct values run from 2 for the binary items to 3,464 for the
examination sampling weight. Three further columns are independent
permutations of the sampling weight, age, and sex. They carry no information
about the outcome by construction and keep each source's marginal
distribution and cardinality.

The replication module loads the cohort from the 15 public files, sets the
documented refused and unknown codes to missing, keeps the complete cases, and
appends the permuted columns. The following code fits a \citrees forest and a

ranking. The permuted sampling weight had a mean rank of 12.1 of 30 under the
random forest, 23.0 under \citrees, and 26.4 under \pkg{partykit}. The primary

also placed the permuted copy of age ahead of 13 real predictors, while both

high-cardinality noise column and agree on the binary one. The reported
diagnoses of hypertension and high cholesterol show the reverse displacement:
the random forest ranked them in its bottom half, and both conditional forests
ranked them in their top ten.

The two controls locate the cause. Ranked by out-of-bag permutation
importance, the same random forest moves the permuted weight to 25.5, between
the two conditional forests. The promotion is therefore a property of
impurity importance on fully grown CART trees, the bias described by
\citet{Strobl+Boulesteix+Zeileis+Hothorn:2007}. Disabling the \citrees Stage A
test leaves the permuted weight at 23.1, so the level $\alpha_{\mathrm{A}}$ is
not what protects the conditional forest here. The remaining candidates are
the choice of the split variable by an association statistic, the capped
candidate set, and the unweighted importance, and this design does not
separate them. The two conditional forests agreed with each other more than
either agreed with the random forest: the per-fold Spearman correlation of
ranks averaged 0.83 between \citrees and \pkg{partykit}, against 0.67 between
the random forest and \citrees and 0.54 between the random forest and
\pkg{partykit}. A ridge-penalized logistic regression on each ranking's ten
highest-ranked columns reached a mean held-out area under the ROC curve of
0.836 for \pkg{partykit}, 0.834 for \citrees, 0.827 for the out-of-bag
permutation ranking, and 0.813 for the impurity ranking. The median fitting
time per training fold was 0.2 seconds for the random forest, 4.8 seconds for
\citrees, and 20.5 seconds for \pkg{partykit}.

\section{Validation} \label{sec:evaluation}

The validation studies measure what a user relies on: that the node tests hold
their level, that split selection does not favor high-cardinality predictors,
that the forests agree with \pkg{partykit} under matched controls, and what
the fits cost. Throughout, size is the rejection rate of a fixed-node test
under its null, and the false-split rate is the rate at which a fitted node
splits under the global null. Section~S2 of the supplement gives the full
designs.

\subsection{Null calibration} \label{sec:calibration}

The selector experiments test predictors generated independently of the
response, with standard normal, binary, or four-level ordinal distributions.
They cover 28 combinations of task, selector, predictor distribution, and
sample size, including the max-$T$ selector combinations, each with 5,000
replicates and 999 permutations. The root experiments fit depth-one trees
under the global null with the Stage A test, the Stage B test, or both
active, under each stopping mode. They cover 78 conditions with 5,000
replicates each, at a budget of 999 permutations, above the floor at which
adaptive stopping is inert.

\subsection{Cardinality and agreement with partykit} \label{sec:cardinality}

The cardinality study gives each replicate 200 observations and five
independent ordered predictors with exactly 2, 4, 10, 20, and 200 levels, and
a response independent of all of them. Trees use 10,000 replicates per task
and forests 2,500, with 100 depth-one trees each. \citrees and \pkg{partykit}
use a familywise level of 0.05 with Bonferroni adjustment over the five
predictors. CART stumps and \sklearn random forests are the impurity-based
comparisons. Each forest is ranked by its native summary. A prespecified
family of 14 trend tests relates cardinality to the selected predictor or to
the importance, with Holm adjustment.

Under this null, \citrees trees split in 4.07\% of classification replicates
and 4.81\% of regression replicates, and \pkg{partykit} trees in 3.64\% and
4.52\%. CART stumps split in every replicate. Table~\ref{tab:cardinality-holm}
reports the trend tests. The \sklearn random forest importance has a strong
cardinality trend in both tasks. The conditional inference forests have
trends of about the same small size in the two packages. The \pkg{partykit}
regression trend of 0.027 was rejected after Holm adjustment, and the
\citrees classification trend of 0.021 was not. The forced-winner trend,
which records the predictor with the smallest $p$-value in every replicate,
was rejected for both conditional inference trees in classification. Among
the replicates in which a tree actually split, no trend was rejected for
either package. The rejected forced-winner trends therefore describe which
predictor attains the extreme statistic, not the fitted decisions. These tests
are upper-tailed; the companion article reports a preference for binary noise
columns under the per-threshold Bonferroni test on designs with signal
\citep{Milletich+Downes+Goley+Hirst:2026}.

\label{sec:behavior}%
The matched comparison fits \citrees and \pkg{partykit} to the Breast Cancer
Wisconsin data and the \sklearn diabetes data on the same 10 repeats of
five-fold cross-validation. Both use depth at most 3, minimum split and leaf
sizes of 20 and 7, all predictors, 999 permutations, and, for forests, 100
trees on full-size bootstrap samples. Each keeps its native statistic,
threshold criterion, random-number stream, and importance. The comparison
was already settled at the design stage for one quantity. Both
implementations split at the root in all 50 fits per dataset, so agreement on
whether to split is 1.000 by construction on these strongly associated data
and does not discriminate between them. Root-predictor agreement is instead a
diagnostic of tie-breaking. Several candidates exceed every permutation and
tie at the smallest attainable $p$-value. With scanning on, the shipped
default, ties are broken by the observed statistic, and the two packages chose
the same root predictor in all 50 fits for both tasks. With scanning off, ties
are broken at random, and agreement fell to 8\% in classification and 12\% in
regression, near the chance levels of 3\% and 10\%.

The informative comparisons are the forest summaries and predictions. Forest
importance concordance by Kendall's $\tau_b$ was 0.480 (95\% interval 0.465 to
0.497) for classification and 0.775 (0.756 to 0.798) for regression, with
top-five Jaccard similarities of 0.616 and 0.793. The classification forests
agreed on 97.0\% of test predictions, with balanced accuracy 0.948 for
\citrees and 0.943 for \pkg{partykit}. The regression forest predictions
correlated at 0.978, with root mean squared error 57.3 and 57.6. Refitting
every model with the same seed reproduced every importance, probability, and
prediction exactly for both packages.

\subsection{Computation} \label{sec:performance}

Two studies time model fitting on 32-core instances. Each fit is the second
of two identical fits in a fresh process, so one-time initialization and
compilation are excluded. Trees have depth at most 3 with minimum split and
leaf sizes of 20 and 7, forests have 100 trees, and the Stage A level is 0.05
with Bonferroni adjustment. \citrees forests are timed with
\code{n_jobs = -1} to match the other libraries' use of all cores, unless a
row states otherwise. Classification uses the multiple correlation selector
and regression the Pearson correlation selector. The \pkg{partykit} timings
use its Monte Carlo Bonferroni test with 999 permutations at depth 3, not its
shipped defaults, so that both libraries run a permutation test at the node.

The first study uses 1,000 observations of 50 Gaussian predictors with signal
in the first five (Table~\ref{tab:performance-reference}). The exhaustive
procedure spends the full budget at every node with exact threshold search and
no sequential stopping, and it is run in both libraries so that they perform
the same work. At equal work, the exhaustive \citrees tree takes 0.17 seconds
against 2.9 in \pkg{partykit}. This ratio reflects parallelism, since \citrees
spreads each test over 32 threads and \pkg{partykit} fits a tree in one
process. The exhaustive forests take 14.6 seconds in \citrees and 13 seconds
in \pkg{partykit} on 32 cores, so the two libraries do the same work in about
the same time. The benchmark configuration takes 0.04 seconds for the tree and
18.6 seconds for the classification forest. The bottom panel decomposes that
forest. Without the Stage B test it takes 0.38 seconds, so the per-threshold
Bonferroni test accounts for 98\% of its time. The max-type test brings it to
1.3 seconds. Fitting the trees serially, the default \code{n_jobs = None},
gives each test the full thread pool and is faster than 32 single-threaded
workers. The permutation budget drives the cost of the exhaustive procedure in
both libraries: at ten times the budget, the forest takes 141 seconds in
\citrees and 2,803 in \pkg{partykit} on one core.

\subsection{Choosing the threshold test} \label{sec:threshold-test}

The companion article compares the two Stage B tests in four designs, which
Section~S5 of the supplement summarizes \citep{Milletich+Downes+Goley+Hirst:2026}.
Both tests are valid at the node. In a design that isolates the threshold
test, the per-threshold Bonferroni test has size 0.000 to 0.027 at nominal
0.05, falling as the candidate count grows, and the max-type test has size
0.023 to 0.044 at every candidate count. At a common nominal level the
max-type test therefore splits more often, and at matched size the max-type
test has slightly less power. The max-type test is cheaper above about 50
candidates and yields a different feature ranking, not a faster route to the
same one. The default remains \code{threshold_test = "bonferroni"} so that
results fit with earlier versions remain reproducible, and the recommended
configuration of Section~\ref{sec:parameters} selects the max-type test.

\section{Discussion and limitations} \label{sec:discussion}

\citrees serves analyses in which the separation of predictor screening from
threshold search is part of the modeling goal, and which need to run inside a
\proglang{Python} workflow. \pkg{partykit} remains the choice for the
reference \proglang{R} behavior and for censored, ordinal, or multivariate
responses, factor predictors, and missing values. A \sklearn forest remains
the choice when fitting time dominates and the importance will be computed by
permutation. Applications should compare predictive performance, feature
stability, and fitting time against both kinds of alternative.

The NHANES case study reproduces on a clinical cohort the ordering that the
cardinality study measures under the null. Impurity importance on greedily
chosen splits promoted a high-cardinality noise column, and every ranking that
either chose the split variable by an association statistic or scored it by
permutation avoided it. The control without the Stage A test ranked the
columns the same way, so on this cohort the conditional choice of the split
variable, not the level, decides the ranking. What the tests add is the tree
itself. A split is made only when an association survives a calibrated test,
so depth is set by a significance level rather than by a pruning parameter
tuned for prediction, and each fitted node records the $p$-values behind it.
On the weak-signal designs of the companion article, permutation importance
on a CART forest keeps the cardinality preference, so the out-of-bag control
reflects this cohort rather than a general remedy
\citep{Milletich+Downes+Goley+Hirst:2026}.

The case study describes one survey cycle and one outcome. Its complete-case
cohort selects on measurement and response patterns. The random forest and
\citrees, which have no factor type, split the unordered categorical columns
as if they were ordered. The forests are compared at their shipped defaults
rather than tuned, and the associations with diabetes are descriptive.
Permutation testing makes \citrees much more expensive than impurity-only
trees, particularly for large forests and many predictors. The exact size of
Section~\ref{sec:scope} applies to a fixed statistic. The adaptive max-type
test recomputes its standardization as permutations accumulate and is covered
by the calibration study only. The package has no tree plot, no case weights,
and no support for missing values.

\subsection{Replication} \label{sec:replication}

After installing the environment with \code{uv sync --group paper}, the
replication suite is run from the repository root with
%
\begin{CodeChunk}
\begin{CodeInput}
$ uv run python -m paper.jss.replication --profile full \
    --output-dir paper/jss/results/replication-full
\end{CodeInput}
\end{CodeChunk}
%
This command regenerates every table in the article and the supplement. The
\code{--profile} option takes the values \code{smoke}, \code{quick}, and
\code{full}. The full profile defines every reported estimate. The quick
profile keeps the same datasets, metrics, and output schemas with fewer
replicates, three-fold cross-validation, smaller budgets, and two timing
repeats. The timing tables require a 32-core machine. Each run writes to a new
directory and validates every component before publishing the result tree.
Component receipts record the profile, seed, source revision, software
versions, and the hashes of inputs and outputs. Section~S7 of the supplement
maps every reported number to its producing component and output file.

Simulation inputs are generated from recorded seeds, and the tutorial data are
distributed with \sklearn. The NHANES workflow downloads the 15 public
component files from the National Center for Health Statistics on first use
\citep{NCHS:2024}, verifies their hashes against values fixed in the analysis
specification, and records them in the receipt.
